# GH-74 — Settings reject unused lifecycle phases

## Problem and cause

The settings screen rejects a valid project environment with an unset execution-plan phase, reporting an invalid type for `workerEnvironment.environment.executionPlan.ready` (or another phase). Backend configuration validation accepts and retains null for all six optional project lifecycle phases. The renderer response decoder required an object whenever a phase was present, so valid saved settings could prevent the entire Settings view from loading.

## Change

Accept null project lifecycle phases in the renderer response schema and represent them in its TypeScript contract. Keep direct executable hooks and populated project commands structurally validated. No backend configuration rewrite, migration, command execution or user state change is needed.

## Validation

- A new regression reproduces rejection before the schema correction using a real backend environment-settings store. It covers both settings response paths, editing, persistence/reopening, null phases and malformed non-null commands.
- Strict TypeScript checks and the production build pass.
- All 41 relevant configuration, environment-settings, discovery and renderer contract tests pass.
- Compiled browser acceptance passes unused project phases, edit/save/reload, existing direct and populated project commands, cancellation, stale edits and narrow layouts. Browser data is synthetic; backend-store regression uses disposable real files. No model turns, lifecycle commands or physical microphone calls occur.
- Screenshots and operational evidence remain outside Git. Full regression suite and native packaged acceptance were not rerun for this renderer contract correction.
