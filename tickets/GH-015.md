# GH-15 — One manager conversation for text and voice

Issue: https://github.com/MattGibney/Crew/issues/15

## Agreed scope

The main manager has one conversation timeline. Spoken user utterances and manager replies use the same attribution, typography, spacing, markdown and grouping as typed messages. Live deltas replace the same message in place; final native records reconcile by identity. Preserve mixed speech/text order, partial honesty, reconnect and history, composer behavior and server-managed handoffs. Worker detail/call navigation is separate in #14; worker approvals are separate in #13. No physical microphone, merge or release is authorized for this implementation.

## Implementation

When supported, the bridge projects canonical native `thread/timeline/list` history and realtime item lifecycle into `work.messages`. Realtime segment IDs are stable; a promoted native item appears once by referenced item identity. The renderer consumes that single state stream and uses `Message.jsx` for every message. Connect never clears conversation history. Unfinished speech is labelled Live while streaming and Partial transcript when the call ends before a final transcript arrives. Only observed text is shown.

The installed app-server advertises the canonical types but its timeline method currently returns the exact response `thread/timeline/list is not supported yet`. That response and method-not-found use the legacy path; operational history errors remain visible. An exact matching-thread native response that history is unavailable before the first user message is an empty-history compatibility case, including after reopening. Verified native fork provenance retains observed speech across history-load failures and retry. Older flat role-based deltas lack utterance correlation. The bounded private conversation journal preserves observed speech in both protocol modes without text-based identity guesses. Native failure remains explicit; unsupported timeline history alone permits the legacy path. The projection never starts turns, appends speech, repeats handoffs or changes approval decisions.
