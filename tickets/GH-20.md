# GH-20 — Realtime user transcript presentation

Issue: https://github.com/MattGibney/Crew/issues/20

## Problem and behavior

A native realtime handoff was displayed verbatim as one user message. Its envelope included both the current input and historical assistant/user transcript context. The You bubble therefore contained internal markup and words from earlier exchanges.

Project the current input into that existing native message. Do not manufacture historical rows, replay the handoff, dispatch another turn or merge independently identified speech by matching text. Incomplete or empty input explicitly reports transcript unavailable until completion. Preserve ordinary tag examples and exact current wording.

## Implementation

`conversation.mjs` owns native user presentation for live items, canonical history and native-turn replay. `conversation-timeline.mjs` repairs old presentation journals during restore. A persisted `realtime-input-v1` marker prevents repeatedly unwrapping current user text that itself contains a literal envelope example. Native chat, turn/item/promotion identity and ordering remain intact. No changes to microphone, audio or native lifecycle.

## Validation

Four added regression checks failed original source before the fix. The final complete npm test run passed 476/476 checks with no failures, skips or cancellations, including the production renderer build. Independent final review found no remaining actionable issue. The packaged runtime modules and ticket matched source byte-for-byte. The compiled UI was checked using an isolated synthetic backend, including live incomplete-to-completed replacement, hidden historical context, retained draft and reload. No physical microphone, subscription turn, installed app, user profile, worker or business repository was used. Screenshots and logs remain outside Git.

Delivery is a feature PR targeting main. Merge, release and installed-app rollout remain separate.
