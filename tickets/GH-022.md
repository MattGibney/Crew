# GitHub #22: preserve worker context across model changes

Issue: https://github.com/MattGibney/Crew/issues/22

The manager can record the user's approved exact model ID and decision for an existing worker. `set_worker_model` requires task/current-run/request identity. It queues only next-turn model intent; the existing turn continues unchanged. Repeating the exact request is idempotent, including after the run advances. Competing lifecycle changes and stale identities are refused.

To move an active worker now, request `worker_action` pause with `cooperative: true`, wait for confirmed owned exit, then explicitly resume. Ordinary approvals remain intact. Setup/runtime recovery and unavailable native context remain blockers; no force-kill, new task, new worktree or replacement conversation is used to make a model change succeed.

The resumed native worker validates the exact ID against paginated `model/list`, supplies it to `thread/resume` and `turn/start`, and requires the native thread response to confirm that model. Missing capability, unavailable ID or mismatch fails before starting a fallback turn. Subscription access or generation can still fail at execution; selection is native configuration evidence, not a guarantee of provider generation success. An account-level error remains visible and preserves the retained work.

Task status and worker details distinguish requested model, pending validation, native selection and failure. Model requests/results form a readable history. The relayed user decision accompanies continuation separately from the original brief and immutable worker behavior. Defaults for other workers/future tasks are unchanged.

Validation: exact catalog/pagination and intent/MCP tests; detached real child-protocol/controller acceptance covering live cooperative pause, controller restart, same thread/worktree/scope and unavailable/mismatch rejection; full suite; synthetic browser acceptance and source packaging. No microphone or business worker is used.

The installed subscription app-server was probed with initialize/account-read/model-list only: the catalog method is supported and the native schema confirms model overrides and the required thread-response model field. No native model work was launched for this probe. Provider-owned model rerouting is observed and disclosed separately rather than silently presented as the requested selection.
