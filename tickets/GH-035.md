# GitHub #35 — Manager name, picture and personality

Issue: https://github.com/MattGibney/Crew/issues/35

Implementation explicitly authorized after initial planning capture. Per-project optional name, local raster picture and free-text personality extend the existing manager voice profile. Settings and manager message/call surfaces present the saved identity immediately. A profile remains an AI manager; audio voice is a separate setting.

Name and personality form a visible, opt-in supplement to the unchanged complete replacement manager instructions. The existing lifecycle snapshots the combined behavior only at first initialization or explicit Start/Restart, passes it through native developer instructions, keyed typed-turn application context, realtime initialItems and realtime start/end instructions, and retains the prior snapshot across controller reload. No new personality engine or automatic turn/call is introduced. Clearing optional fields removes their supplement after the next explicit activation. A configured name is used for introductions in place of the audio voice name; no name preserves existing greeting behavior.

Pictures are embedded local PNG/JPEG/WebP data with MIME/signature, base64, 512 KiB and 2048-pixel bounds. The renderer additionally decodes the selected file and provides a Crew fallback for failed display. SVG, external URLs and arbitrary local paths are not accepted. Picture data never enters model instructions. Names are bounded to 80 characters, personality to 8,000; combined instructions retain the existing 64,000-character limit. Invalid, stale or oversized writes preserve prior settings. Legacy voice-only records load without overwriting their selected voice; the next explicit save atomically writes schema 2.

Preservation scope: complete custom prompts, selected voice, persistent native chat, task/run/worker records, Codex configuration and approvals. No dependency on or incorporation of scratchpad PR #36. No version bump, merge or release.

Validation: `npm test` includes focused store/HTTP/native-protocol/renderer boundary tests. `scripts/manager-profile-native-acceptance.mjs` exercises the compiled renderer, actual Electron/controller/storage/IPC with disposable profiles and synthetic provider/media.
