# GH-62 — Shared agent preparation for updates and explicit Quit

[Issue #62](https://github.com/MattGibney/Crew/issues/62) began with a 0.15.0 → 0.16.2 update stall: workers displayed Paused while the update was blocked on manager activity and retained pause-requested progress. The human explicitly expanded implementation to a common agent-owned preparation protocol for updates and explicit Crew Quit. Deliver a PR only; no merge, version bump or release.

## Findings and implementation

The manager completion race reproduces in exact v0.15.0 and typed main: a manager finishes during awaited worker pause enqueue, then strict interruption rejects a now-null active turn. Blocked local/group plans also stopped observing late pause proof. This is inherited, not established as a TypeScript regression; the reported user's precise cause remains unverified without exact blocker state/text. Narrow before-fail regressions/fix remain, but are not the completed feature.

The shared preparation design is recorded in [PREPARATION.md](../docs/PREPARATION.md). Durable requests/responses bind purpose, project, participant, conversation/run and request identity. Ordinary MCP tools expose the scoped request and durable preparing/ready/needs-input/blocked response, optional factual continuation and idempotent retries. Existing native conversations receive the request without a replacement conversation; delivery attempt, native acknowledgement and agent reply remain separate. A lost transport reply is never replayed blindly. A scoped agent response may independently establish receipt.

Ready acknowledgement is separate from execution settlement. Native final events/results, journal writes and fresh worker/runtime/hook proof must settle before shutdown. Natural-settlement lifecycle intent never interrupts the turn or runs environment stop commands. Agents own resource preparation. Completed assignment results and workflow remain intact and are not automatically replayed. No acknowledgement is fabricated for already stopped/never-started execution. Missing active delivery, approval or unknown resource evidence remains a concrete blocker.

The native parent holds all projects, renders per-participant delivery/readiness/settlement and uses the same barrier for explicit Quit. Every exact child marker is confirmed before any controller stops. Prepared controller shutdown closes the native peer cooperatively and flushes persistence rather than falling through the force-signal path. Quit reopening keeps continuation behind explicit recovery. Closing a window is unchanged; OS shutdown/power integration is excluded.
