# AI-005: Select and audition a Codex voice

Scope: user-authorized voice dropdown in the existing browser manager, plus a brief selected-name greeting on each successfully connected call. Preserve ChatGPT subscription authentication, v3 transport, manager instructions and worker/controller state. No API keys, generated sample gallery, accent/gender claims, personality changes or automatic microphone activation.

Implementation: supported thread/realtime/listVoices supplies the current v3 catalog, validated and cached by the bridge. Dropdown uses display names and marks the Codex default; localStorage saves the next-call choice. Connect sends the selected ID, checked again against the actual server catalog. Unavailable catalog disables Connect and offers retry. Selector locks during call setup, connected call and disconnect, with a reconnect explanation.

After successful browser WebRTC connection, a session-bound opaque token permits one thread/realtime/appendSpeech request: “Hi, <selected voice name> here.” This uses the selected session voice and v3 speakable channel, not a fake user utterance or backing model turn. Duplicate connected/ready events cannot repeat dispatch; disconnect invalidates the token. Failed speech requests are not retried automatically because delivery can be uncertain. Failed connection attempts and SSE reconnects do not request a greeting. Audible delivery and interruptibility remain human acceptance checks.
