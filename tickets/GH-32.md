# GitHub #32 — Preserve chat scroll position

[Issue #32](https://github.com/MattGibney/Crew/issues/32) tracks the user's report that chat updates jump toward the top instead of holding position or following the bottom.

The Message Scroller was configured with user-message turn anchors and last-anchor opening. Its anchoring behavior can move a new user row toward the top even while following the bottom. The compiled-renderer regression reproduced the failure on new-message/completion arrival before this fix.

Open at the end, omit turn anchors, and use an 8 px edge tolerance for fractional geometry. The existing primitive retains reader position and follows growth only at the bottom. Keep stable canonical message IDs and the explicit Jump to latest control; no message-array scrolling effect, transport or conversation-state changes are needed.

The synthetic browser acceptance exercises loaded history, repeated state refreshes, readers in history and just above the bottom, appended user/assistant messages, streamed growth, completion, Jump to latest and composer resizing. It launches no model, worker or microphone. Test artifacts remain outside Git.

Validation passed: fresh renderer build and all 498 regression tests, the dedicated scroll browser acceptance, and existing worker-navigation/call-persistence acceptance. Isolated source Electron acceptance with real local controller and synthetic provider verified retained-history opening, reading-position preservation, Jump to latest, bottom-following appends, voice off and normal Quit exit zero. The native check waits for smooth scrolling to finish rather than assuming a fixed duration. No release or published artifact is changed by this fix branch.
