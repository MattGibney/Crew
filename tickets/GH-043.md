# GitHub #43 — Worker archive

Source: https://github.com/MattGibney/Crew/issues/43

## Agreed behavior

Archive replaces Remove worktree and requests the existing protected teardown. Pending/failed teardown stays visible and actionable. Confirmed success removes ordinary cards, counts, attention and default manager status entries while preserving history. Completed, stopped and paused workers remain retained until explicitly archived.

Project Settings provides a simple project-scoped table, one row per archived worker, newest known archive time first. Rows offer Restore and Delete permanently only; no archive detail/editor. Unknown legacy times remain explicit.

The user chose history-only Restore. It returns the same historical record to the ordinary workspace with History restored and unavailable-environment guidance, without resource recreation, setup, queued assignments or worker/model turns. Native thread/run/prompt/result/history identities remain intact. Old questions and approvals remain historical. Later environment recreation is separately manager-directed; automatic reconstruction is not implemented by this action. Start/Resume cannot pretend a runnable environment exists. Explicit rearchive verifies terminal execution plus owned worktree/Git registration absence, then moves only the record without claiming cleanup ran again.

Permanent deletion needs consequential confirmation bound to the current record revision. It removes only the selected archived worker's local Crew JSON/Markdown/notes, run evidence and native-approval records. Fresh liveness checks, canonical path/symlink protection, project guards and durable operation identities protect retries and partial deletion. Minimal deletion journals prevent accidental task-ID reuse. Global Codex history, auth, unrelated tasks, worktrees and services stay outside this action.

## Implementation

Shared worker-archive projections serve renderer, manager tools, native counts, attention and approvals. Raw records remain available for exact historical lookup. Controller archive completion and its timestamp are atomic. Legacy dispose remains compatible with the archive alias. Restore and permanent-delete HTTP operations use same-origin/update-admission guards and preserve calls/drafts. Restored native approval decisions and delivery are rejected without fabricating a response.
