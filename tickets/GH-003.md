# GH-003 — Project instructions and manager lifecycle

Source: [GitHub issue #3](https://github.com/MattGibney/crew/issues/3). Implementation authorized for an isolated feature branch and a separate PR targeting main. No direct-main push, merge, tag or release is authorized by this work.

## Delivered behavior

- Focused project Settings: complete manager/worker instruction editors, separate save/reset/cancel, accessible labels and responsive layout.
- Full replacement of Crew-authored behavior, including voice startup greeting and attention-review persona/tone. Provider rules, sandbox enforcement and required runtime/tool correlation remain separate.
- Durable project-local saved content hashes, active/retained manager versions and pending restart. Manager changes activate only on explicit Restart or Start after Stop; workers retain immutable original snapshots across continuation.
- Safe manager Start/Stop/Restart. Held interactions, visible transitions/errors, confirmed native interruption/approval resolution and process exit, retained history and independent workers. No automatic work, voice connection or capture.
- Immutable worker prompt text/version review in task details. Exact untouched pre-settings defaults upgrade without rewriting config files; customized text and existing snapshots remain unchanged.
- Technical and user guidance in docs/SETTINGS.md, current configuration/README/AGENTS updates and the project Notion architecture page.

## Validation evidence

- Disposable actual-server HTTP tests: save/reload/stale/origin/invalid requests, native instruction parameters, restart application, stopped-controller recovery, preserved history/task state and no automatic work/voice.
- Child JSON-RPC lifecycle tests: active turns, unresolved approvals, delayed starts, duplicate actions, interruption errors, held state, realtime stop and a surviving independent worker process/durable report.
- Detached worker tests inspect the actual CLI prompt and retained snapshot on question/resume; newly launched workers receive newly saved behavior.
- Compiled React UI tested in desktop and 390px layouts: edit/save/pending/restart, reset/cancel/navigation, typing during an in-flight save, stopped interactions, worker details and synthetic media release. Screenshots and proof files remain outside Git.
- Disposable installed subscription Codex app-server check passed prepare, saved changes pending restart, restart activation, Stop hold and Start with the same native chat ID. No turn, voice or microphone was started.
- Renderer production build, official shadcn-theme compatibility and curated source packaging checked. The source archive includes the new modules, UI and docs; it is a candidate review artifact, not a release.

The first broad run had worker observation timeouts; successful exit/result records arrived after its old five-second test polling limit. That helper now waits up to twenty seconds with last-state diagnostics, preserving the worker's runtime limits and all assertions. A later concurrent run encountered separate existing environment-hook timing/stop-evidence failures. The final serial regression passed all 250 tests using `node --test --test-concurrency=1 tests/*.test.mjs renderer/src/manager/*.test.mjs renderer/src/setup/*.test.mjs` (171 seconds), without presenting the earlier concurrent failures as passes.

## Boundaries

The installed Crew app/config/history/workers were untouched. No real project source/provisioning, shared service, external business ticket or physical microphone changed. Human acoustic greeting/device acceptance remains separate. Multi-project routing/shared-cap integration and coordinated updater pause/drain/resume integration belong to their independent PRs and need combined tests after integration; this PR supplies per-instance settings/lifecycle endpoints and update admission guards.
