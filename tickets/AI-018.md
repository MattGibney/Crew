# AI-018 — Pause work safely, update and selectively resume

Status: In progress; integration and UI acceptance underway. Delivery: feature PR against main, no new release/tag or automatic merge.

User-authorized scope: replace manual update-blocker workarounds with an explicit Pause work and update action. Freeze new admissions, durably capture task/run/manager identity, cooperate with the existing controller to pause owned work and verify shutdown, install only after readiness, then resume only eligible work paused by this update. Preserve unknown states, questions, approvals, sessions, dirty worktrees and resources. Never force shutdown or replay manager input automatically. The affected installation is on another Mac; it has not been inspected or modified.

Implementation: atomic local update-plan.json journal, fail-closed launch hold, targeted idempotent cooperative pause requests, fresh execution evidence and exact target-version installation marker. Manager and workers drain independently; an interrupted manager remains interrupted. Running bounded setup phases complete, then pause before launch. Worker interrupt has no force escalation. Persistent runtime pause uses declared stop commands only. Native updater retains its exclusive lease, other-instance checks and fresh admission reservation.

Cancellation retains the hold and paused work. Resume paused work explicitly resumes only eligible correlated targets; Return to work releases admissions without resuming paused targets. Missing evidence, unresolved questions/approvals, unknown ownership, missing runtime stop commands or failed install remain actionable blockers. Automatic recovery never opens voice/microphone.

Acceptance: concurrent disposable registered worktrees and actual owned child processes; targeted cooperative pause and signal evidence; retained session/worktree identity; no queued launch while held; exact selective resume with duplicate prevention; cancel, timeout, failure and restart recovery; built UI and native coordinator decisions. Tests use disposable fixtures, not business repositories. Signed native installation of this feature awaits a user-directed grouped release; do not publish a test release merely to prove it.

Initial combined acceptance passed three real-process/controller/native-decision journeys.
