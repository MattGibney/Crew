# GH-38 — Duplicate primary chat bubbles

Ticket: https://github.com/MattGibney/Crew/issues/38

## Evidence and scope

The reported screenshot shows repeated primary user bubbles and a completed written
manager answer followed by a similar spoken answer. Private screenshot/chat data
stays outside Git and public tickets. The issue was created before implementation.

Read-only retained native history confirms one backing execution turn with separate
voice transcript, native delegation request, commentary/final response and spoken
summary records. The bridge passively observes these; transcript events do not
start work or relay its result. This establishes presentation duplication for the
inspected exchange, not a universal absence of duplicate execution.

Transcript records provide item/session identity, role and text, with no native
handoff/turn linkage. Equal words or adjacency cannot establish that linkage.
Native work and spoken output can have different content and both must survive.

## Intended correction

Keep realtime speech in ordinary conversation bubbles. Classify native backing work
only from existing standalone delegation-envelope provenance and its exact native
turn. Show consecutive backing records in expandable Work details at their original
positions; retain each request, commentary and written answer. Never move an entire
turn across intervening speech. Ordinary typed messages and deliberately repeated
utterances stay separate. Legacy presentation journals retain provenance, including
when the bounded window no longer contains the original delegated request.

Canonical same-ID completion replaces live text without reopening it on late starts;
replayed history updates the same IDs. Interrupted speech remains visibly partial.
This changes presentation only, preserving native chat, handoffs, transport/audio
ownership, the single SSE consumer and all work/approval behavior.

## Acceptance boundaries

Use compiled renderer and child-protocol fixtures for streaming/final, canonical
hydration, restart/reconnect, repeated utterances, partials and retained written
content. Autonomous media is synthetic; no physical microphone is authorized.
A disposable subscription websocket/text probe authenticated but returned a realtime
error before transcript events. It started zero turns/tools and exited normally;
actual provider streaming/commit identity equivalence is not established by that probe.

Delivery is a focused feature-branch PR to main. No merge, release or version bump.
