# Agent-owned project browsers

Each stable agent owns its browser workspace and tabs. The owner chooses which workspace and tab to display; tool callers always control their own active tab, regardless of the workspace visible in the owner UI. The earlier #56 single-page prototype remains the basis of the scoped per-tab CDP boundary.

## Owner flow

Open **Browser**, choose an agent, enter a local app URL or an explicitly permitted public website, and open the page. Public websites require both **browser · control** and **browser · external** in the agent’s current assigned groups; neither is granted automatically. You may use an explicit development hostname when its system DNS results contain only loopback addresses; the URL and HTTP Host routing stay unchanged. Back, forward and reload act on the selected tab. New tab may start blank until a permitted URL is entered. Closing a tab leaves the other tabs; closing the selected agent browser leaves other agents' browsers running. Selecting an agent does not start it. Browser ownership survives stopping/restarting its native session; each actual tool call must still come from the exact current started session. The selected agent must also have a project-scoped **browser · control** permission in an owner-approved group. No existing/default group receives it automatically.

Choose **Select element** and click a page element, or **Annotate page**. Feedback is sent on **Send annotation**, through existing owner-attributed agent messaging, to the recipient captured when annotation began. A selection does not run the clicked page action. The message carries URL/title, capture timestamp, optional selector/text/bounds and an opaque screenshot reference. `browser_annotation_image` returns that stored image only to its recorded recipient with current browser permission and current session. Annotations must target the tab's owner, and metadata records the stable owner agent and tab IDs. Element selection and screenshot have separate timestamps when capture occurs at send time; the screenshot is not a claim of current page state after later navigation.

## Composition contract

`createUnifiedProjectBrowser` in `src/browser/unified-browser.mts` takes:

```ts
{
  projectId, stateDirectory,
  getWindow: () => BrowserWindow | undefined,
  getHostOrigin: () => string,
  getAgent: (agentId) => Agent | null,
  publish: (event: { type: 'browser', projectId, state }) => void
}
```

It exposes `state()`, owner-authenticated `request({projectId,action,...})`, `close()` and `tools({authorization,runAuthorized})`. Read-only inactive state needs no native agent/session. Main must authenticate the selected owner/project before `request`, forward state through the existing desktop event bridge, and close the old browser before project/window shutdown. Route the allowed preload method `browser` to this service; do not add a new unauthenticated renderer API.

Combine the existing skill extension and `browser.tools(context)` through `combineAgentToolExtensions`. The existing foundation MCP authenticates exact logical sessions; browser execution additionally checks stable agent ownership, the exact current started session and fresh `browser.control` authorization. Tool discovery uses `canDiscoverBrowser`: it verifies the exact current starting/started session and current project-scoped group permission, without requiring an open page or owner selection. It never calls execution admission or starts a model turn. The stable catalogue is generated from pinned `chrome-devtools-mcp@1.12.0` tools/list, allowing native sessions that cache tools at startup to discover schemas before a browser is shared. Regenerate after a serialized build with `node scripts/update-browser-catalogue.mjs`; generation asserts zero browser connections. Actual dispatch goes through `runAuthorized` and rechecks the caller before upstream I/O. The outer workspace dispatcher holds one execution-admission gate; the inner tab dispatch rechecks ownership/session without reacquiring that gate. Extension `subscribe` refreshes catalogue notifications without granting access. Generic schema-validated `{crewMcpResult}` results preserve image content; durable invocation correlation remains in the normal MCP host.

The minimal optional AgentsApp slot receives `{snapshot,selectedAgent,client,visible}`. DesktopApplication supplies `ProjectBrowser`. The view remains mounted while hidden, hides its native child bounds outside Browser, and preserves other conversation/voice components. State events always describe the owner-selected workspace. Hidden tabs retain a 1280×800 viewport for background tool screenshots; changing UI selection hides the previous native view without destroying it.

## Isolation and tooling

Each agent has a private persistent Electron session, shared by its tabs but isolated from other agents and Crew. Cookies and local storage can survive native-session restart and app relaunch; the tab registry and active selection currently live only for the desktop process lifetime. No personal browser cookies or credentials are imported. Every tab has no Crew preload, Node or IPC bridge, denied permissions/downloads/popups, and an origin filter applying to redirects/subresources. Explicit owner or agent URL navigation can switch a tab to another allowed local HTTP origin by replacing its scoped preview. Local preview tabs permit one origin at a time. Public tabs follow the additional #127 policy below. Different tabs may use different explicitly selected local origins. Request filtering is registered once per agent session and selects the tab policy by WebContents identity; opening another tab must never overwrite an earlier tab's filter. Crew's own origin and loopback-port aliases are rejected. The generic policy has no application-specific hostname rules. Direct networking is set only on the preview session to avoid inherited remote proxies; Chromium's system resolver is checked before opening and before each permitted request, rejecting unavailable, empty or mixed loopback/non-loopback results. This trusts the local development resolver configuration; it is not an OS-level hostile-DNS/network sandbox.

Same-host/same-port `ws://` transport is allowed for the explicitly selected HTTP preview, so normal dev HMR can operate. It does not permit WebSocket navigation, another loopback hostname/port, a Crew port, secure/remote WebSockets, or a second origin. Other API/CDN origins remain blocked. Owner-selected local naming does not authorize editing the preview application's tooling, source or DNS setup.

A scoped browser-level CDP facade exposes only one tab. Raw Electron app-wide debugging is not an agent capability: it exposes Crew's host even when host DevTools are disabled. The independent Chrome DevTools MCP 1.12.0 client attaches to the scoped endpoint; no Chrome/browser launch, personal profile, model auth or service credential inheritance occurs. Its tool process uses a private HOME, explicit environment and disabled config discovery/telemetry. Unknown tool outcomes are never automatically retried. Shutdown closes stdin, then may terminate only that owned tool process; unknown exit is retained as failure, never followed by a force kill.

Browser tools preserve upstream `pageId` schemas. Use `browser_list_pages`, then `browser_take_snapshot`, navigation, fill/click, script evaluation and screenshots. Use `browser_tabs` for stable tab IDs, `browser_new_tab` to create a blank/permitted tab, `browser_select_tab` to choose your own tab, and `browser_close_tab` to close it. These four schemas are available alongside the original 15 schemas before any browser is opened. `browser_list_pages` enumerates the active tab's scoped CDP target rather than the workspace. Global browser management, file navigation and unsupported domains remain unavailable.

## Permission-controlled public browsing — #127

Add `browser.external` alongside `browser.control` to an owner-approved group and assign that group to the intended agent. The canonical action catalogue automatically includes the new capability in group Settings. Existing groups and presets gain no authority. `browser.external` alone never permits a public page. Owner Browser opens use exactly the chosen agent’s current group authority; choosing an agent or opening Browser grants nothing and starts no native session. Existing local HTTP preview behavior remains available. Native agent tools retain their exact current started-session and ordinary `browser.control` admission checks.

Public tabs accept HTTP/HTTPS navigation, public redirects and cross-origin public website assets/API requests, plus WS/WSS network transport. Top-level file/data/blob/about/chrome navigation stays blocked; inline data/blob subresources can render without adding network authority. URL credentials are rejected. Chromium’s uncached system resolver must return exclusively public addresses for every network request. Loopback, LAN, link-local, reserved/multicast, mapped/transition IPv6 and Crew’s own host origin are rejected. An autonomous public page cannot use this capability to connect to a local preview; explicit owner/agent navigation to a local URL instead creates a local-scoped view. Custom hostnames resolving only to loopback retain local preview mode even for agents granted public browsing.

Authority belongs to the agent’s assigned group, independent of native-session liveness for page traffic. Normal page JavaScript can initiate requests while its tab is open, including when hidden or the agent is stopped, only while both grants remain current. Every request rechecks group authority before DNS and again after DNS; cached native tool schemas or a prior open are never permission. Each native browser tool controlling a public document also checks the current public grant. Committed assignment/group changes notify the browser service, which closes revoked public native views immediately, ending their document and existing transports before waiting for MCP process cleanup. Historical tab entries/URLs and private per-agent cookies/storage are retained; reopening needs fresh authority. Revocation cannot undo a request already completed or retract bytes already received.

Session request interception is installed once per agent partition and dispatches by WebContents ID, so new tabs never overwrite older tabs’ policies. Unknown/background requests without an owned tab identity fail closed; service-worker/offline and child-target parity are not promised. No personal profile, subscription credentials or app-wide CDP endpoint is exposed. Permissions, downloads, popups and webviews remain denied; non-proxied WebRTC UDP is disabled. Local networking bypasses inherited proxies. This browser-layer policy trusts the OS/Chromium resolver and network stack; checking DNS separately from Chromium connection establishment is not an OS-level defense against a hostile resolver/rebinding or malicious native machine. Strong hostile-worker network isolation requires a separate network sandbox.

Focused acceptance uses `node --import tsx --test tests/public-browser-policy.test.mjs`, `node scripts/public-browser-permissions-acceptance.mjs`, and `CREW_PLAYWRIGHT_MODULE=/absolute/path/to/playwright-core/index.mjs node scripts/public-browser-native-acceptance.mjs` after serialized typecheck/build. The native fixture uses disposable real Electron views, per-tab CDP facades and MCP tool subprocesses with synthetic agent/session/group sources, plus harmless public GET requests. These checks establish scoped browser functionality; signed-in-model and owner visual acceptance remain separate.
