# Concurrent worker lifecycle (AI-011)

The human talks only to one persistent manager. The manager submits explicitly agreed ticketed assignments to independent Codex workers. Each task has its own Git worktree, Codex session, durable JSON record and readable Markdown projection. Local task status is not Linear ticket status. The manager checks the actual existing ticket before repository work; setup does not create or mutate tickets.

`project.worker.maxConcurrent` controls executing capacity (1–8, default 2). Extra explicitly submitted tasks queue; no automatic backlog selection occurs. A worker that asks a question ends its turn and releases execution capacity. Answers are bound to that task/question/run and resume the same conversation/worktree. Reports and meaningful attention remain queued without forcing speech or opening the microphone.

Manager `worker_action` requests are durable and correlated by action ID, target task and expected run. Retry uses the same ID. Stop/pause ends only the target's owned execution and retains partial work, conversation and evidence. Resume/start creates a new attempt after reconciliation. Completed work remains available until deliberate disposal; dirty worktrees are not forcibly discarded. Controller restart adopts verified surviving execution instead of launching a duplicate. Each task reconciles independently so one failure cannot stall the rest. Closing voice/window does not stop the controller or detached workers. Quitting the instance stops its controller; retained workers and reports are recovered when the instance starts again.

## Optional environment hooks

`project.worker.environment` can define `bootstrap`, `start`, `ready`, `resume` and `cleanup` hooks. Each hook is `{ "command": "/absolute/executable", "args": ["argument"], "timeoutMs": 60000 }`. Commands execute directly without a shell, in the isolated worktree, with bounded execution and a unique `CREW_ENV_ID`, `CREW_TASK_ID` and `CREW_WORKTREE`. Hook attempt/results are retained by a separate bounded supervisor that survives controller exit. Process ancestry and start identity are captured across process groups; teardown waits for confirmed descendant exit. Missing or unresolved ownership blocks disposal rather than claiming success. Hooks must be bounded foreground lifecycle commands. A foreground start hook cannot leave background process daemons behind: its captured descendants are reaped when the phase ends. This release does not supervise persistent application-service daemons. Project-specific bounded lifecycle tooling remains responsible for external resources named by that environment identity. Cleanup must target only those resources.

Without hooks, Crew proves worktree/execution isolation only, not application-service readiness. With hooks, recorded successful readiness means that configured check passed, not that all business behavior is verified. Bootstrap/start/readiness run before first execution; resume/readiness check retained environments; explicit disposal runs configured cleanup after stopping and checking retained work. Set1's `./tools/dev`/Nx/shared ClickHouse/MinIO integration is not automatically configured or proven. No Set1 environment or shared data is deleted by this release. Disposable fixture hooks test the generic contract.

The minimal existing worker list shows every active task and recent terminal records, useful progress/attention and current-run execution timing. It is not a full worker-card dashboard or a synchronized Linear status view. Execution elapsed time uses the recorded execution interval rather than counting waiting time as active work.
