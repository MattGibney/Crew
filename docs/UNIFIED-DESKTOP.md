# Unified desktop integration (#95)

The package entry, development entry and `crew start` open `src/desktop/main.mts`. That host starts the canonical `startUnifiedApplication` composition for each registered project. It does not start the legacy manager controller. The renderer reuses Crew's existing conversation, workers, scratchpad, profile controls, settings layout and semantic theme.

## Ownership and boundaries

- The desktop registry owns project selection, canonical source folders, the presentation port and the selected voice. Each project composition owns agents, conversations, approvals, access, environment execution and native sessions. The saved primary agent is explicit; an empty primary selection never falls back to the first agent.
- The static loopback server serves only pinned renderer assets. Owner commands use the bounded Electron preload and must originate from the current main frame and exact origin. Owner-entered service credentials cross that bridge only through dedicated save operations and are not read back into agent or settings views. Native authentication stays in the isolated Codex store; the owner UI receives only the information needed to complete sign-in and its status. Images are validated private project files read through owner IPC, never an HTTP state route.
- Skills are project-owned native `SKILL.md` bundles with immutable selected revisions. The composition's authorization/admission wrapper governs their agent tools. See [Project skills](PROJECT-SKILLS.md).
- Voice uses the composition-owned primary voice service. The desktop adapts validated owner commands; it does not create another handoff, turn or settlement authority. One mounted renderer hook owns media while controls move between presentation modes. Explicit Connect is required; automated validation uses synthetic media.
- Per-agent schedules reuse the existing cadence/checkpoint engine and have no default occurrence. The desktop passes the scheduler's current-state check into foundation admission, where it runs before persisting private delivery intent. A disabled or changed schedule is rejected there without leaving a queued message.
- Guided project setup walks through Sign in, Project folder, Agent, Access, Connections and Review. The selected folder has explicit no-access, read-only and read-write choices. The final action prepares its exact policy, saves a visible shared access group and applies the reviewed assignment through the existing access authority. Approval of a path alone does not grant an agent access or prove actual project execution.

## Guided setup (#100)

The first-use screen creates the manager without asking the owner to configure an approved preset manually. Later, **Create agent / update access** in the worker area and **Agent setup** in Settings open the same flow. Existing-agent repair changes access while preserving its profile and conversation. Shared groups can be reused; creating a new named group never rewrites a group used by other agents. Current permissions from every selected group appear in the final review.

Setup progress is a private, revision-checked record of non-secret choices and completed stages. Credentials and sign-in URLs stay in their existing authentication flows. **Save and close** pauses the form; reopening resumes it. A concurrent saved revision leaves typed choices visible and requires an explicit discard-and-reload action. Ordinary error refresh preserves unsaved input. Completion uses stable group and creation-configuration identities, recovers an already allocated agent from its exact provisioning provenance and fails closed when a creation attempt cannot be resolved. It never retries an uncertain creation by allocating a second agent. A known folder-preparation failure before any access mutation returns to an editable draft; uncertain or committed access changes retain their recovery checkpoints.

Connections are optional. Local-only work can use Crew capabilities and the selected project folder. Saving the setup creates a stopped agent; Start remains explicit. Access repair applies to subsequent authorized tool calls without replacing the native chat. Profile changes retain their separate Restart behavior.

The environment tools accept `agentId: "self"` and resolve it to the authenticated caller before normal authorization. An agent with access only to its own project folder can discover and attach that folder without a separate permission to list the team. Explicit targets still require their normal permission checks.

## Native lifecycle

Closing the window releases voice/media and keeps the menu-bar host and independent work alive. Explicit Quit prepares all projects and observes the same readiness request while conversation remains available. Final reservations are acquired for every project before any project is closed. If closing begins but cannot be confirmed, retain reservations and offer Retry Quit under those exact reservations. A retry skips cleanup stages already confirmed complete; it does not release reservations or resume queues before disposal. Releasing a partially disposed composition is not a safe Return to work.

Updates adapt the existing signed-update coordinator. A shared installation lease covers startup and installation, and other native instances are checked. Explicit installation requires fresh all-project reservations. Unsigned candidates cannot establish a stable update feed or install automatically. This track does not install or replace the user's existing Crew app.

The renderer retains submitted and newly typed drafts across async acknowledgements. Settings editors remain mounted across navigation and agent selection, and revision conflicts preserve the user's draft. A successful access save remains acknowledged if its following refresh fails; Retry refresh repeats only the read and preserves pending drafts. A rebuilt pinned renderer requires a controller restart before native validation; a successful build does not update an already open editor.
