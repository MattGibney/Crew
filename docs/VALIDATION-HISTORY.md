## Verification practices

- Test saved values and exact command/source provenance, not only labels or schema.
- Separate queued dispatch, actual public command evidence, a matching completed harness turn, durable result and independent host verification.
- Exercise concurrent tasks, task/question/run/action correlation, cancellation, surviving-process adoption and refusal of unresolved ownership.
- Verify owned process identities across process groups and independently preserve unrelated resources.
- Before claiming background behavior, close the window once and inspect lifecycle/HTTP/process evidence without reactivating it.
- Check browser permission denial, cancellation during pending capture, release/blur/disconnect cleanup, reload and responsive behavior with explicit synthetic-media limits.
- Verify packaged source/resource integrity and local API/origin/preload boundaries. A successful build alone does not prove installed native behavior.
- Keep raw logs, screenshots, private repository acceptance settings and session/resource IDs outside Git. Public release evidence must be deliberately sanitized before publication.
