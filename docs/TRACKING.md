# Optional tracking and connected workflows (GitHub #78)

Crew facilitates one manager conversation, durable local tasks, optional issue linkage and normal connected tools. Tracking is an agent workflow, not a Crew service client or automatic backlog engine. Project setup offers none, Linear, GitHub or both; preferred tracker guides new work only. No integration availability check gates ordinary dispatch.

## Issues and retained work

Ask the manager to find/read an explicitly selected issue and its description, state, labels, comments and links using available authenticated tools. GitHub identity includes owner/repository and number; Linear includes its provider, exact identifier and canonical URL. Same-number issues in different repositories/providers never identify the same task. The assignment brief carries actual returned issue context and evidence limits. Follow-up uses the existing conversation/worktree and retains the issue link unless explicitly changed for that new assignment. Earlier assignments, results and history stay immutable. Worker Overview and Links show supplied issue URLs; local work shows **No external tracker**. Legacy labels remain visible without claiming current access.

When explicitly requested, the manager can create/comment/update issues through existing tools. Bind every action to the exact repository/provider/object and check returned identity and result before claiming success. Unknown transport is not evidence of a successful action or permission to retry blindly. There is no cross-provider sync, automatic pickup or automatic issue closure on worker completion. External issue state, agent workflow and native execution remain separate.

## Pull requests, reviews and checks

Associate PRs with a task only from actual issue links, closing references or repository evidence; never infer a PR from a branch name. Through normal tools read PR metadata/head, changes, submitted reviews, review threads and checks/statuses for that head commit. Summarize in the existing manager conversation and shared work notes, including source URLs, repository/PR identity, observed head SHA, observation time and missing coverage. Review findings differ from a submitted approval/change request. A successful status does not prove all check runs passed; empty, missing, pending and inaccessible data remain distinct.

Re-read the PR head after collecting checks/reviews. Changed or mismatched head makes the earlier evidence stale, never passing/approved for the new commit. A review can target an older commit even while the PR head is unchanged; report its actual commit and dismissal/resolution state where available. Surface incomplete pagination and unsupported methods rather than claiming complete review/check coverage. Normal tool discovery, auth and approval support vary by native Codex version/connection; a repository read alone does not verify these methods.

Explicitly requested review/comment actions use normal tools with exact object identity and returned confirmation. Enabling GitHub never publishes a review, merges, reruns a workflow, pushes or releases. The manager remains the single user contact. Crew adds no business-action permission gate or replacement GitHub UI.

## Evidence and migration boundaries

Configuration is a saved mapping. Advertised tool capability is discovery. Verified access requires an actual read of the relevant object; each operation may have different coverage/permissions. Saved state is retained on denied/partial access. Retry or change/disable optional tracking in Project setup. Custom instructions stay full replacements; only exact pristine shipped defaults migrate, and manager activation still requires explicit Start/Restart. Active manager/worker snapshots and historical labels are retained.

Local automated fixtures validate configuration, persistence, dispatch and presentation; synthetic tool responses do not prove live provider behavior. Packaged disposable profiles validate native integration separately. External writes need explicitly authorized disposable targets and are not implied by local test permission. Physical audio and automatic updater behavior are outside this feature.
