# Working scope and durable engineering guidance

- Tie implementation to an appropriate Crew ticket and explicitly agreed scope. Keep AGENTS guidance current when the user corrects a working assumption. Maintain clear technical and user-facing documentation; private operational evidence belongs outside the public repository.
- Use existing ChatGPT/Codex subscription sign-in and allowance. Never add API-key fallback, extract private credentials/endpoints or copy another machine's auth files. Keep feasibility checks bounded and disposable.
- The human converses with one persistent manager. Preserve native server-managed realtime handoffs; transcript/handoff events must not launch duplicate turns or relay results twice. Keep normal approvals and truthful correlation of dispatch, execution and result evidence.
- Opening the app or selecting a mode never activates the physical microphone. Explicit Connect in default open-mic mode authorizes capture after connection unless explicitly muted; preserve mute intent across reconnect/error. Ordinary blur/hidden retains open mic and releases PTT only. Mute/cancel/disconnect cancels pending permission and stops tracks; window destruction disposes transport/audio resources. Generated silence is transport, not microphone evidence.
- Preserve user-controlled voice choice and session-bound at-most-once startup greetings. Catalog availability, append acknowledgement, generated audio packets and human acoustic acceptance are different claims. Do not fabricate a user utterance or work assignment to trigger output.
- Exactly one project belongs to each local controller/config/state/port/chat instance. One installed Crew app owns multiple such isolated instances through its parent workspace registry. Never guess repository, branch or Linear mappings; actual ticket access is checked before explicitly agreed work. No automatic backlog or startup model task.
- Repository workers use genuine registered pinned worktrees and separate subscription Codex sessions. Default to read-only; local edits/tests require explicit scope. Commits, pushes, pull requests, merges, external ticket changes and deployments require their own supported authorization.
- Concurrent task lifecycle requests must be durable, idempotent and scoped to task/run/action identity. Question answers must match the exact question/run. Closing a window or voice leaves independent work running; stop preserves partial work and evidence. Dirty worktrees or uncertain ownership block disposal.
- Reconcile surviving owned processes without duplicate launches. Verify PID/start/command identity across process groups before signaling descendants; require confirmed exit rather than merely recording a stop request. Distinguish fresh liveness, task status and supported execution timing.
- Use established project configuration, AGENTS/docs and shared development instructions unchanged. Crew is a client of project tooling, not a replacement provisioner. Do not require a project-specific API, source patch or experimental branch to use the generic runtime.
- Execution plans retain exact command/source hashes, setup-once evidence, persistent Start, optional readiness and explicit teardown. Resume verifies retained data and never silently reruns setup. Missing or ambiguous cleanup requires a manager decision; do not guess destructive commands or clean shared resources.
- Ordinary project developer configuration can inherit local settings and enable background integrations. Worktree isolation does not establish provider isolation, application readiness, hostile-worker safety or production correctness. A successful teardown command does not prove every project resource was removed; disclose observed residuals.
- Preserve bounded sanitized failure diagnostics with separate stdout/stderr budgets. Use compact globally unique worktree basenames because downstream tooling can derive constrained resource names from them. Readable task IDs remain in records.
- Default macOS state paths contain spaces. New worktrees may use a private persistent ~/.crew/worktrees instance namespace while retained legacy roots stay unchanged. Verify canonical paths, Git registration and ownership; never silently move retained worktrees.
- Setup automates reversible configuration when evidence supports it: canonical folder, sensible names, existing branch and actual connected-tool team/project choices. Preserve custom runtime settings and user state; ask only unresolved decisions. Cancellation, stale evidence and failed validation leave saved settings safe. No setup action starts project commands, a worker or capture.
- Keep one canonical renderer/src/styles/theme.css with official semantic Tailwind/shadcn tokens and approved branding. React components/hooks own the UI; preserve origin checks, bounded preload, file identity checks and a single manager SSE consumer. Rebuild then restart a source controller before testing pinned assets.
- Worker cards keep all current work/history reachable. Local status differs from live process evidence and unavailable Linear title/status. UI actions go through the manager with stable correlation; never introduce direct worker conversations or invented progress/ETA.
- Preserve submitted and newly typed drafts during async UI updates. Narrow-screen worker Review returns to the manager. Retain configuration/readiness errors while refining presentation.
- The Electron window is a disposable control surface; close releases voice and leaves the owned backend/menu bar running. Explicit Quit is separate and stops only the owned controller, while detached workers retain their evidence. No microphone on startup, automatic login service or wake-lock behavior.
- Do not hold the ESM entry module open with top-level await on app.whenReady(); use a readiness callback and verify a real packaged launch. Unit checks alone do not establish native lifecycle behavior.
- Native accessibility observation can reactivate a closed app. For background acceptance, close once, inspect only lifecycle/HTTP/process evidence, then reopen. If the user leaves the Mac locked, do not bypass security; continue independent browser/headless/build checks and report native/device acceptance as pending.
- Keep local configs, credentials, conversations, task/run/worktree state, installers and screenshots out of Git. Crew is the current product name; legacy names and local.voice.manager remain compatibility identities. Migration must preserve state/profile provenance and offer recovery rather than reset, merge, force-stop or blind relocation.
- Historical test evidence stays separate from current human acceptance. Before a fresh human worker test, preserve automated records in an archive and leave the intended current task list empty. Never launch/answer/acknowledge the user's acceptance work on their behalf.

## Update readiness correction (AI-017)

Unknown evidence blocks with specific task/phase guidance; never mark resources stopped, delete a worktree or stop Docker/shared services merely to clear an update blocker. Preserved partial provisioning can outlive a stopped setup command.

## Managed project toolchains (GH-1)

- Crew owns project Node/npm selection and installation in a shared per-install cache (`~/Library/Application Support/Crew/toolchains` on macOS; `~/.crew/toolchains` on Linux). Build an explicit PATH from compatible exact managed versions and required system utilities, with controlled worker shell startup; never rely on personal shell startup files, guess version-manager paths, change global tools or substitute arbitrary newest versions. Preflight inspects requirements without installation; the first authorized worker preparation installs missing versions. Use the resolved environment consistently for setup, Start/resume, readiness, teardown and worker execution.
- Existing committed project configuration and AGENTS/Claude/development commands remain authoritative and unchanged. Managed tool installation is authorized for this feature; no project-specific API, source patch, paid service or credential extraction is required. Worktree dependencies/builds stay isolated, but worktrees and the tool cache are not a filesystem/container security sandbox.
- A failed setup with `harnessStarted: false` does not establish that no project resources were created. Preserve its evidence and partial state; never silently replay incomplete setup or clean/reseed shared services. Recovery cleanup requires explicit resource-scoped authorization. Symptoms reported from another Mac do not prove its precise original cause or current state.

- GH-1 acceptance distinguishes real tools with a synthetic worker from actual subscription-worker execution. A packaged acceptance should use its own config/profile and bundled runtime, verify actual command/report/result and confirmed exit, and leave voice off. First-run setup is expected until that config is reviewed. Completed tasks intentionally reject resume; use confirmed natural completion as clean-stop evidence rather than rewriting state to force a resume.

## Coordinated update scope (AI-018)

- Explicit Pause work and update authorizes a durable local batch lifecycle plan through the ordinary controller. Freeze new admissions/launches, close voice without microphone capture, interrupt the correlated manager turn honestly, and cooperatively pause captured workers. This narrow update action is an exception to manager-mediated worker UI actions; it never starts a worker conversation.
- Update pause sends only a verified cooperative interrupt and waits for owned execution to exit naturally; bounded setup phases finish before the pause boundary. Persistent project runtimes require declared stop commands. Never force-kill, teardown, auto-answer questions/approvals or clear uncertain evidence to install. Update voice shutdown failures must block without forcing the manager runtime; the renderer releases local tracks and cancels pending input as soon as it observes the plan.

## Delivery policy correction

- Feature/fix work belongs on codex/ feature branches with reviewable pull requests targeting main. Do not push implementation directly to main or automatically merge. Group features into releases only when the user explicitly requests the intended release; do not create a release/tag or dispatch publication for every small change. Preserve existing main history and published artifacts. Release workflow dispatch is a deliberate user-authorized stage after review, not a completion requirement for each ticket.

- Disposable controller/process tests must register cleanup before their first observation wait. Distinguish a generous ordinary fixture lifetime from an intentionally short timeout under test; wait for correlated lifecycle completion rather than assuming an awaited tick ran when another tick was in progress. Keep test-only timing changes separate from product timeout/no-force guarantees.

## Multiple workspaces (GitHub issue #2)

- The native parent owns the workspace registry, selected window, tray, shared capacity and app-wide update/Quit. Per-project closures own controllers, config, prompts, sessions, state, worktrees and retained Chromium partitions. Register existing paths and identities in place; do not move state or merge chats.
- Workspace switching disconnects the departing backend voice and destroys its renderer; destination voice stays off until explicit Connect. Preserve unsent drafts in project-partition storage. Background workers continue; selecting a project never changes admission priority.
- Validate canonical config, prompt and state boundaries before bootstrap and before every setup save/discovery apply. Startup-only validation does not prevent later cross-project collisions. Keep config ports independent of inherited legacy port environment overrides.
- Shared admission uses the durable global ledger and verified-owner lock. Unknown runs retain their slots. Reopen reconciles workers but holds stored queues for explicit manager start/resume; attention and rendering cannot authorize execution.
- All-project update reservation pauses global admission before local reservations. Require positive reservation/cancellation confirmations, retain uncertain holds and journals, and recover only the intended installed version with every project verified idle. Do not restart unreviewed controllers on update cancellation. The separate coordinated pause engine, Settings lifecycle and managed toolchains require combined integration acceptance after their independent PRs are integrated.
- Per-project storage recovery/relaunch must route through parent all-project shutdown. A native second-instance launch with an explicit config must register/select that project rather than silently dropping it.
